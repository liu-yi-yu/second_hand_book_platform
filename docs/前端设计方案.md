## 一、总体形态

| 项 | 决定 | 理由 |
|---|---|---|
| 技术栈 | 纯 HTML / CSS / JavaScript（ES Module），**零依赖、零构建** | 不需要安装 Node，也不需要任何打包工具 |
| 位置 | `src/main/resources/static/` 目录 | Spring Boot 会自动把这个目录作为静态资源根目录对外提供 |
| 访问方式 | 启动后端后，浏览器直接打开 `http://localhost:8081/` | 前端与后端**同源**（同协议、同域名、同端口），从根本上避免了跨域(CORS)问题——后端目前没有配置任何 CORS |
| 路由 | hash 路由（`#/login`、`#/books/xxx`…） | 单页应用(SPA)最简单的路由方式，刷新不丢页面，服务器无需额外配置 |
| 后端端口 | **8081**（来自 `application.yml` 的 `server.port: 8081`，需求文档里写的 8080 已过时） | 代码为准 |

## 四、接口契约 —— 以后端代码为准的适配清单

前端**必须**按下面这份清单对接，它反映了 yu-test1 的真实行为（与需求文档的差异已用 ⚠ 标出）：

### 4.1 全局约定

| 项 | 后端实际行为 |
|---|---|
| 基础路径 | `http://localhost:8081/api` ⚠（文档写 8080） |
| 响应信封 | 成功 `code=1`、失败 `code=500` ⚠（文档约定成功为 0；BusinessException 携带的 40001 等码在全局异常处理器中被覆盖成 500，只保留 message） |
| 未登录/过期 | JWT 拦截器返回 HTTP 200 + `{"code":40101,"msg":"未登录…"}`（注意字段是 **msg** 不是 message）→ 前端据此清除会话并跳登录页 |
| 管理员校验 | `{"code":40003,"msg":"…"}` 同上 |
| JSON 字段命名 | 全局 Jackson `SNAKE_CASE`：请求体和响应体的字段都是下划线风格（如 `selling_price`、`image_ids`） |
| 认证头 | `Authorization: Bearer <token>`；**单 token** ⚠（无 refresh_token，也没有 `/api/auth/refresh` 接口） |

### 4.2 各接口要点

| 接口 | 后端实际行为 / 前端注意点 |
|---|---|
| `POST /api/auth/register` | body `{username, email, password}`；返回 `data.token` → 注册即登录 |
| `POST /api/auth/login` | body **`{username, password}`** ⚠（文档写 email，代码用 `selectByUsername`）；返回 `{token, id, username, email, avatar_url}` |
| `GET /api/users/me` | 返回字段：`avatar`（不叫 avatar_url）、`score`（不叫 credit_score）、`selling_count`、`sold_count`、`created_at`、`bio` |
| `PUT /api/users/me` | ⚠ 参数走**查询字符串**（Controller 没有 @RequestBody）：`?avatarUrl=…&bio=…`；后端 update SQL 目前**缺 WHERE 条件**（已知问题，前端界面放置风险提示） |
| `GET /api/users/:id` | 返回 `avatar_url`、`credit_score`（注意与 /me 的字段名不同） |
| `POST /api/books` | body 下划线字段；**原价必填** ⚠（@NotNull）、**ISBN 必填** ⚠（service 里 `isbn.split` 会 NPE）；成功后 `data=null` ⚠（不回显书籍） |
| `PUT /api/books/:id` | ⚠ 后端会**先删光旧图片关联再按 image_ids 重插**——编辑时必须把现有图片 id 一并带上，否则图片会被清空；状态 removed 的书修改后自动变回 selling（可当"重新上架"用：传空 body `{}`） |
| `DELETE /api/books/:id` | 逻辑下架（status→removed） |
| `GET /api/books` | 分页参数 **`pageNum`/`pageSize`** ⚠（不是 page/page_size）；排序 `sortBy` 传 **SQL 片段** ⚠：`updated_at desc` / `selling_price asc` / `selling_price desc` / `view_count desc`；价格区间 `minPrice`/`maxPrice` 实际按**原价**过滤 ⚠；`keyword` 在 title/author/description 中模糊匹配 |
| `GET /api/books/:id` | `original_price`/`selling_price` 是**字符串** ⚠；`images:[{id,url,thumbnail_url}]`，`thumbnail_url` 恒为 null ⚠（无缩略图，前端用占位图）；`seller:{id,username,avatar_url}` |
| `POST /api/upload/image` | `multipart/form-data`，字段名 `file`；返回 `{id, url, thumbnail_url:null}` |
| `GET/POST/DELETE /api/cart` | 加购 body `{book_id}` 返回购物车总数（数字）；列表项 `{id, book:{id,title,author,status,condition,cover_image}, seller:{...}, selling_price, created_at}`，后端已过滤非在售书，`cover_image` 恒 null ⚠；移除 `DELETE /api/cart/{book_id}` |
| `POST /api/cart/checkout-preview` | body `{book_ids:[…]}` → `{cart_item_vo_list, total_price, count}` |
| `POST /api/orders` | body `{book_ids:[…]}` → `data` 直接是 **OrderVO 数组** ⚠（无 data.orders 包装）；失败时 `data=null`；订单 ID 是**自增整数** ⚠（文档写 UUID） |
| `GET /api/orders?role=buyer|seller` | 分页 `pageNum`/`pageSize`，status 可逗号分隔；列表项 `{id, book_id, book_title, book_cover_image, amount, status, counterparty_name, counterparty_avatar, created_at, …}`，**列表为空时 `data=null`** ⚠；`created_at` 因类型转换缺失可能为 null ⚠ |
| `GET /api/orders/:id` | OrderVO：`buyer`/`seller`/`book`(BookSimpleVO) + 各时间戳 + `cancel_reason` |
| `PUT /api/orders/:id/confirm|ship|receive` | 分别是卖家确认 / 卖家发货 / 买家收货，无请求体 |
| `PUT /api/orders/:id/cancel` | ⚠ 请求体是 **JSON 字符串字面量**（如 `"不想要了"`），不能发对象；只有 pending 状态能取消 |
| `GET /api/orders/:id/messages?limit=50` | 返回 `{message:[…], has_more}` ⚠（字段名就叫 message）；消息**最新在前**，前端渲染时倒序；无消息时 `data=null` ⚠；消息字段 `{id, order_id, sender_id, receiver_id, content, client_id, created_at}` |
| `PUT /api/orders/:id/messages/read` | 进入聊天页时调用，标记该订单消息已读 |
| `GET /api/messages/unread-count` | → `{count, by_orders:[{order_id, title, user_name, count, content}]}` ⚠（文档写 total/by_order） |
| `POST /api/reviews` | body `{order_id, rating, content}` ⚠（文档字段叫 comment）；**只有订单状态为 received 时才允许** ⚠（文档说 completed）；每人每单只能评一次 |
| `GET /api/users/:id/reviews` | → `{records, total, avg_rating, review_count, rating_map}` |
| `GET /api/notifications` | 分页 `page`/`pageSize`/`unreadOnly`；→ `{page_vo:{records,total}, unread_count}` ⚠；通知项 `{id(整数), type, title, content, is_read, related_order_id, related_book_id, created_at}`；**后端默认只返回未读** ⚠（isRead=0 过滤） |
| `PUT /api/notifications/read` | body `{ids:[1,2]}` 标记指定，`{}` 或省略 ids 全部已读 |
| WebSocket | `ws://localhost:8081/ws/chat?token=<裸token>`；上行 `{type:"send_message", order_id, content, client_id}`、心跳 `{type:"ping"}`→`{type:"pong"}`；下行 `{"type":"connected"}`、确认 `{type:"message_ack", client_id, message_id, created_at}`、推送 `{type:"new_message", message:{id, order_id, sender_id, sender_name, sender_avatar, content, created_at}}` |
| `GET /api/admin/users` | `page/pageSize/keyword/role/status` → PageVO{records(UserProfileVO),total}；**VO 里没有 role/status 字段** ⚠（无法显示，只能显示 username/信誉分等） |
| `PUT /api/admin/users/:id/status` | body `{"status":"active"|"disabled"}` |
| `GET /api/admin/books` | **只返回前 15 条** ⚠（后端写死 PageHelper(1,15)） |
| `PUT /api/admin/books/:id/remove` | 强制下架 |
| `GET /api/admin/orders` | 只返回前 15 条 ⚠，且**无书名/对方字段** ⚠（SQL 是 select * from orders） |
| `PUT /api/admin/orders/:id/cancel?reason=…` | ⚠ reason 是**查询参数**不是请求体 |
| `GET /api/admin/dashboard` | `{total_users, active_users7days, total_books_selling, total_orders, completed_orders, total_sales, order_status_count:[{count,status}], new_orders7days:[…]}` |

### 4.3 枚举对照（后端枚举为小写字符串存库）

- **分类 category**：`literature` 文学小说 / `textbook` 教材教辅 / `professional` 专业书籍 / `comic` 漫画 / `children` 儿童读物 / `other` 其他 / `novel` 小说 / `magazine` 杂志 ⚠（文档的 8 个值不同）
- **成色 condition**：`brand_new` 全新 / `like_new` 几乎全新 / `used` 有使用痕迹 / `old` 较旧 ⚠
- **书籍状态**：`selling` 在售 / `sold` 已售出 / `removed` 已下架
- **订单状态**：`pending` 待卖家确认 → `confirmed` 待发货 → `shipped` 已发货 → `received` 买家已收货 → `completed` 交易完成；`cancelled` 已取消
- **通知类型**：`order_created / order_confirmed / order_shipped / order_received / order_completed / order_cancelled / new_message / review_received / book_sold_out / system`

## 五、核心交互设计

1. **登录守卫**：路由器在进入需登录页面时检查 localStorage 里的 token，没有就跳 `#/login`，并记住来源页面，登录后跳回。
2. **统一错误处理**：`api.js` 里集中处理——业务失败 toast 后端 message；40101/40102 清会话跳登录；其余异常提示"系统异常"。
3. **聊天**：全局维持一条 WebSocket（登录后连接，30 秒一次 ping 心跳，断线自动重连）；发送消息先用本地 `client_id` 乐观上屏（半透明"发送中"），收到 `message_ack` 后转正；收到 `new_message` 时——若正在对应聊天页就追加气泡并自动标已读，否则 toast 提醒并刷新未读徽标。顶栏徽标每 30 秒轮询一次（通知未读 + 聊天未读）。
4. **下单流程**：购物车勾选 → `checkout-preview` 弹窗确认（总价/件数）→ `POST /api/orders` → 跳转订单列表。信誉分低于 60 的用户下单时前端弹警告（文档 3.10 的软约束）。
5. **订单操作按钮**按"角色 × 状态"渲染：卖家 pending→[确认订单][取消]；卖家 confirmed→[发货]；买家 pending→[取消]；买家 shipped→[确认收货]；received 状态双方出现[评价]按钮（后端仅允许 received 评价）。
6. **图片**：上传后保存 `{id,url}` 列表；发布/编辑提交 `image_ids`；**编辑页必须预填已有图片**（否则后端会清空图片关联）。
7. **管理后台**：进入时先探测 `/api/admin/dashboard`，返回 40003 就显示"无管理员权限"占位页。

## 六、已知后端问题（前端不改代码、只做提示，供后续修复参考）

1. `PUT /api/users/me`：`UserMapper.update` 的 SQL **没有 WHERE 条件**，一旦传了 bio/avatar 会更新**所有用户**；且 Service 未传 id。→ 前端在编辑资料处放置醒目风险提示。
2. 聊天历史 `getMessages`：`PageHelper.startPage(max, limit)` 把"总条数"当成了页码，消息超过 1 条时历史查询会返回空（修复建议：改为 `startPage(1, max)` 或 `startPage(page, limit)`）。→ 前端按契约渲染，空则显示"暂无历史消息"，实时消息不受影响。
3. 管理员书籍/订单列表写死只返回前 15 条；订单列表缺书名/买卖双方字段。
4. 图片无缩略图（thumbnail_url 恒 null），书籍列表封面恒为空 → 前端统一使用占位图。
5. 订单列表/详情的 `created_at` 因 BeanUtils 类型不匹配可能为 null → 前端显示"—"。
6. 发布书籍必须传 ISBN 与原价（否则后端 NPE / 校验失败）→ 前端设为必填。
